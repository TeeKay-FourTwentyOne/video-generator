after delivery of v4-4k. The local master is 2160 by 3840, 30 fps, 720 frames
and 24 seconds, with SHA-256
`c3030c78a61295b58ef68bc8d77202f91d2b7ba147b0d6a0ab2fafc5cd6f0d0e`.
The recording date is not an inferred platform publication date, and the hash
identifies the local file, not YouTube's transcode. The exact user-edited
[description](description.md) is the canonical wording and credit order.

The archive retains the final 4K review package; all twelve original material
studies and their prompts, references and pair selections; numerical arrays and
diagnostics; all original detector and field-air stems; procedural picture
masters; edit recipes; frozen revision scripts; and historical delivery and QA
records. Superseded full edits, the six 4K assembly segments and the two complete
soundtrack mixes are disposable derivatives. Their historical hashes and review
events remain recorded after removal. The lossless 4K counterpart is retained
as a reusable procedural picture source and comparison reference.

The creative motion study and its status-page copy remain as source studies.
The retained v2 tail and v3 opening are inputs to the third revision's join.
Library masters and private recovery bundles are preserved. Archive integrity
and project backup are separate checks; neither certifies a standalone rebuild.

Restore a verified copy into a new active workspace before making changes.
Frozen requests contain historical paths. For those recipes, recreate the old
workspace layout in an isolated checkout or deliberately adapt a working copy;
never edit the sealed archive to make an old command work. Dependencies include
the repository, FFmpeg, the provisioned Python environment, imported clip
masters and their retained analysis, acceptance records and edit manifests.

To reconstruct removed derivatives, rebuild the v1 soundtrack from its retained
synthesis recipe and inputs, then assemble v1. Recreate v2 and v3 in order if
using the original recipes that copy the prior version's encoded audio. Rebuild
the v4 soundtrack from its retained detector stems and original field-air input,
then assemble v4 from the retained v3 picture. The 4K finish uses the retained
lossless counterpart and copies v4's encoded soundtrack. Full versions in a
restored copy must use fresh output folders; the scripts refuse overwrites.
These are dependency instructions, not a claim that a complete rebuild has
been qualified or will reproduce identical encoded bytes.

Required project analysis is complete for all six imported clips. Model semantic
review states and historical listening/approval records remain unchanged.
Publication is its own later event.

## Process improvement

During finishing, already-complete project analysis triggered an expensive
search rebuild across unrelated historical runs. The maintained processing CLI
now accepts `--defer-search-refresh`: it still processes and verifies every
required project source and analysis artifact, writes completion receipts and
explicitly records that search coverage is deferred. Its default is unchanged.
`npm run clips -- analysis index` remains the separate discovery refresh.
Regression tests cover fresh processing, reuse, missing required passes, corrupt
sources and a later ordinary search rebuild.

Archive retention also accepts explicitly hashed versioned complete mixes under
`audio/`, using the same transaction as their `edit/` equivalents. Tests retain
the protections for source stems and reject missing or mismatched review hashes.
