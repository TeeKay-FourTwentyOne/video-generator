# Extract clip metadata before local cleanup

Status: baseline pipeline, resumable queue, local-adapter contracts, private search,
reviewed public projection, complete analysis backup/recovery, and a fail-closed
cleanup-readiness report are implemented. See [commands and current limits](clip-analysis.md).
The semantic profile now has [explicitly provisioned local models](clip-analysis-setup.md)
and structured timing/retrieval contracts. It still requires a labeled human-reviewed pilot
and recovery/access/dependency evidence before any cleanup. The information table
below remains the target capability set; implemented measurements must not be
mistaken for completion of every proposed detector.

The [next implementation handoff](clip-analysis-handoff.md) prioritizes a qualified
local semantic profile, including speech timing, visual observations and retrieval.

Build a new resumable pipeline around the current content-addressed clip library.
Keep useful legacy annotations as attributed evidence, and run fresh extraction
against verified original bytes. The objective is to preserve enough measured data,
searchable content and small previews to discover and select footage without
downloading each master. New questions may still require restoring the original;
no finite set of annotations captures everything a video contains.

## Starting point

The catalog inventory on 2026-10-14 contains 2,106 unique files representing about
17.6 hours, including derivatives and deliveries. There are 256 classified sources,
332 derivatives, 283 deliveries and 1,235 files of unknown kind. Existing automated
analysis is attached to 280 clips, character-cluster annotations to 76, generation
records to 256 and immutable creation snapshots to one. These counts describe
recorded evidence, not the number of clips actually generated by a model.

Relevant earlier work:

| Existing code or records | Reuse | Replace or qualify |
| --- | --- | --- |
| `tools/production/clip-library.mjs` and `catalog/` | Hash identities, schema checks, imports, source/use joins | Extend analysis through a versioned schema; keep JSON authoritative |
| `mcp/video-generator/src/services/clip-metadata.ts` | Extraction categories and adaptive frame-sampling ideas | Filename IDs, mutable shared database, shell command strings and three-frame default |
| `mcp/video-generator/src/services/analysis.ts` | FFmpeg scene, black, freeze and silence detector concepts | Default transcription can call an external paid API; caught failures can become missing/negative results |
| `docs/clip-metadata/` | Historical summaries, transcripts and frame annotations already imported | Preserve their original attribution; they are not newly verified observations |
| `scripts/face-detection/` | Anonymous character grouping as an optional continuity aid | Reassess dependencies, accuracy, persistence and public projection; retain embeddings privately |
| `tools/clip-qa.py` | Temporal anomaly categories and useful reporting shape | Its paid vision calls need a separate authorized adapter and ledger reservation |

Implement the new coordinator under `tools/production/`; use argument arrays and
structured parser output. Do not run the legacy batch entry point as a shortcut.
In particular, filesystem modification time is not generation time, unavailable
transcription is not silence, and a failed visual detector is not a clean result.

Capture adjacent evidence before cleanup as well: saved jobs, request/operation
records, prompt files, reference hashes, source acquisitions, edit recipes and
existing QA decisions. Much of this cannot be recovered from video pixels or
container tags. Join by verified hashes or unambiguous historical mappings, retain
the original evidence privately with its own hash, and label later extraction as
historical evidence. Never turn a mutable film plan into a creation-time snapshot.
The current clip mirror does not back up these arbitrary workspace documents;
include the selected evidence in the new manifest allowlist before removing it.

## Information to extract

Every finding refers to the input hash, stream and actual presentation timestamps.
Store exact rational time bases and frame indices where defined. Variable-frame-rate
clips must not be timed by multiplying seconds by a nominal frame rate.

| Pass | Outputs | Method and limits |
| --- | --- | --- |
| Identity and provenance | SHA-256, bytes, container tags, attached metadata/subtitles, generation snapshots, source/derivative and edit-use links | Preserve raw tags privately. Distinguish measured properties, original creation evidence and historical reconstruction. Missing model, seed, rights and creation time remain unknown |
| Technical structure | All streams, codecs/profiles, bit depth, pixel format, dimensions, sample/display aspect, rotation, frame rate/time base, PTS/DTS, frame/keyframe counts, bitrate, duration, audio layouts/rates, color primaries/transfer/range and HDR side data | FFprobe plus a complete decode. Retain a compressed frame/timing table and decoder diagnostics; never silently normalize the master |
| Visual structure and signal | Cuts, fades, black/frozen/duplicate frames, scene spans, exposure/clipping, sharpness/blur proxies, noise/blocking hints, luminance/color histograms, palette, borders and flicker measurements | Decode all frames for inexpensive signal checks; persist detector versions and thresholds. A still shot, fade or darkness is not automatically a defect |
| Motion and composition | Motion magnitude/direction, camera movement candidates, subject tracks/counts, framing/shot size, screen direction, foreground/background and approximate composition | Optical flow/tracking plus temporal model observations. Label camera motion, depth and lens impressions as estimates |
| Visual meaning | Timecoded scene descriptions, subjects/objects, settings, actions and changes, lighting, weather, style, mood and editorial keywords | Local vision model on ordered, timestamped frames or short windows. Link each claim to evidence; unseen events and inferred intent are not facts |
| Visible text | OCR text, language, boxes, confidence and appearance intervals; subtitles, signs, titles and watermark-like marks | Start with native OCR or a portable local OCR adapter. Retain original spellings separately from normalized search text. Review text before any public projection |
| Speech and vocals | Audio presence, VAD spans, language hypotheses, verbatim transcript, word/segment times, uncertainty and optional speaker turns | Local ASR after VAD; compare transcript spans with audio evidence. Music, breathing and sung vocals require separate handling. Speaker labels describe local clusters, not real identities |
| Audio signal and content | Loudness/true peak, clipping, silence, waveform envelopes, channel correlation, spectrum/noise measures, speech/music/ambient/event spans, optional tempo/key/instrument estimates | FFmpeg signal measures plus a local audio classifier/embedding model. Do not confuse absent audio, quiet audio and failed analysis; short music excerpts may have indeterminate tempo/key |
| Similarity and reuse | Image/text/audio embeddings, perceptual hashes, near-duplicate families, potential subclip alignment and repeated motifs | Exact SHA-256 remains identity. Similarity is a candidate relationship, not proof of shared bytes or provenance; reuse annotations only through verified temporal mappings |
| Editorial usefulness and QA | First/last-frame descriptors, candidate clean ranges and handles, loop/seam suggestions, continuity/anatomy/morphing flags, soundtrack suitability and search terms | Keep automated suggestions distinct from artistic acceptance. Reference-based quality scores require an actual reference; sampled frames cannot certify every frame |

Keep creation prompts separate from observed descriptions. A prompt can inform an
intent-comparison pass, but the first content pass should describe what is visible
without being told what the generator was supposed to produce.

## Local tools and sampling

Start with FFprobe/FFmpeg for technical and signal extraction. Their documented
filters include scene, black, freeze and silence detection, signal statistics and
loudness analysis. Use the installed binaries, recording exact versions and build
options. See the [FFmpeg filter reference](https://ffmpeg.org/ffmpeg-filters.html).

For the initial semantic pilot, use local Whisper through
[whisper.cpp](https://github.com/ggml-org/whisper.cpp) with VAD, native
[Apple Vision OCR](https://developer.apple.com/documentation/vision/recognizing-text-in-images)
on macOS, and a quantized
[Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct) candidate
through [MLX-VLM](https://github.com/Blaizzy/mlx-vlm). These are starting choices to
measure on the available hardware, not a quality or throughput guarantee. Pin
runtime revisions, weight hashes, quantization, preprocessing and model licenses
before the pilot. A portable OCR adapter should share the same result schema.

Use [OpenCLIP](https://github.com/mlfoundations/open_clip) for a first image/text
retrieval index, and evaluate [CLAP](https://github.com/LAION-AI/CLAP) for local
audio/text similarity and candidate sound-event labels after the baseline pilot.
Similarity scores are not calibrated event probabilities; speech transcripts
alone do not describe a soundscape. Run one
large model at a time and record peak memory, elapsed time and output size. Model
downloads are explicit setup steps; analysis must work offline once provisioned.
An external vision/ASR service is an optional later adapter, requiring active
provider, scope and budget authorization before any clip or frame is sent.

Run technical decode and inexpensive signal statistics across the entire clip.
For expensive semantic passes, start with first/last frames, a one-frame-per-second
grid and frames on both sides of cuts and detected changes. Deduplicate unchanged
frames; analyze long material in overlapping scene/window chunks. Escalate sampling
around motion, brief text, uncertainty or disagreement. Keep frame and window
coverage in each result: one frame per second can miss brief events. The pilot
should determine where denser OCR and temporal inspection are worthwhile.

Retain a poster, timecoded contact sheet, selected keyframes, waveform, subtitles
and a small seekable preview with audio. Preserve source-to-preview timing and any
display conversion for rotated, anamorphic or HDR material. Avoid permanent raw
frame dumps. Set preview size limits from measured pilot outputs and the authorized
storage capacity, then include their projected footprint in the private plan.

## Evidence and storage contract

Private output layout:

```text
data/clips/<clip-id>/analysis/<run-id>/manifest.json
data/clips/<clip-id>/analysis/<run-id>/steps/probe/technical.json
data/clips/<clip-id>/analysis/<run-id>/steps/timing/frames.jsonl.gz
data/clips/<clip-id>/analysis/<run-id>/steps/signal/scenes.json
data/clips/<clip-id>/analysis/<run-id>/steps/audio/audio.json
data/clips/<clip-id>/analysis/<run-id>/steps/transcript/transcript.json
data/clips/<clip-id>/analysis/<run-id>/steps/ocr/ocr.json
data/clips/<clip-id>/analysis/<run-id>/steps/observations/observations.json
data/clips/<clip-id>/analysis/<run-id>/steps/embeddings/
data/clips/<clip-id>/analysis/<run-id>/steps/preview/
```

The manifest records schema/extractor versions, source hash, complete settings,
tool/model/weight identities, time bases, timestamps, sampling coverage, resource
measurements, warnings and every output hash/size. `run-id` derives from immutable
input and extractor configuration. Runs are append-only; retries resume incomplete
steps or create a new version when settings change. Preserve competing model
observations instead of replacing them with an unexplained merged answer.

Each extractor has `pending`, `running`, `complete`, `not-applicable`, `failed` or
`needs-review` state. Record a reason for `not-applicable`; a failure cannot become
an empty successful result. Confidence includes its source and interpretation;
model self-confidence is not a calibrated probability. Human corrections attach
to the observation they revise and do not rewrite the original output.

Use per-clip locks, atomic completion manifests and a resumable queue. Hash inputs
before work and verify identity again before completion. Limit CPU/model workers,
temporary disk use, execution time and free-space consumption. Persist progress
after every extractor so an interrupted overnight run does not repeat completed
analysis or report a half-written result as complete.

The existing public `analysis` schema cannot hold these detailed results. Add
versioned public analysis references and an allowlisted summary projection after
schema design, keeping raw OCR, transcripts, embeddings, preview images, logs,
provider receipts and private source tags in ignored storage. Projection requires
privacy review; never automatically commit new text extracted from media. Keep
measured data and inferred descriptions distinguishable in search results.

A local SQLite/FTS and vector index can accelerate search, but it is disposable:
rebuild it from the JSON records and private embedding files. Search should return
a clip ID, matching time range, evidence type, preview and local/remote presence.
Presence is private operational state; the public `availability` field describes
public hosting and must not be repurposed to expose the private backup.

## Implementation sequence and acceptance

1. **Inventory and baseline.** Reconcile library IDs with historical local copies
   and dependency locations; classify unknown kinds without dropping them. Add the
   run schema, queue, full probe/decode, timing tables, signal measures and previews.
   Start with every unique clip, including unknowns; prioritize source/unknown clips
   for semantic work and deduplicate derivative work only when mappings are proven.
2. **Pilot semantic extraction.** Use 24 clips selected across portrait/landscape,
   short/long, speech/music/silence/no-audio, visible text, people/animation,
   static/moving scenes, cuts and known defects. Supplement with disposable fixtures
   for rotation, HDR, variable frame rate, corruption and edge cases absent from the
   library. Hand-check timestamps, OCR, transcripts, concrete descriptions and
   retrieval relevance. Record errors, time, memory and artifact size privately.
3. **Choose and run the profile.** Freeze extractor/model versions and required
   passes using pilot evidence. Run across the library with a coverage dashboard,
   retries and a review queue. Optional costly passes remain visibly unrun unless
   authorized; never silently count them as complete. Export private JSON and
   reviewed public summaries and build search/preview views.
4. **Back up analysis and support absent local masters.** Extend the explicit cloud
   allowlist to immutable analysis manifests and their declared artifacts. Preserve
   their dependencies and reject unsafe paths or undeclared payloads. Add a complete
   backup-set manifest linking clip identity, catalog digest, creation snapshots,
   required analysis runs, object generations and checksums. Teach plan/sync to
   verify already-backed-up remote masters when local bytes are deliberately absent;
   missing unverified media must still fail. Add analysis restoration and verify
   the private snapshot mapping on recovery.
5. **Rehearse and report cleanup readiness.** Restore media, metadata and analysis
   on an empty checkout using only remote objects and independently recoverable
   access configuration. Verify all hashes and dependency references and rebuild
   search. Produce a per-clip readiness report and proposed cleanup list. Deletion
   remains a separately authorized action after these prerequisites are satisfied.

Tests should exercise meaningful failures: corrupt inputs, truncated downloads,
missing/changed snapshots, interrupted extraction, changed model settings, output
hash mismatches, VFR timing, silent/no-audio handling, failed ASR/OCR, duplicate
imports, private-text projection, missing backups and pending edit dependencies.
Verify that offline extraction never calls a provider, existing artifacts survive
reruns, and queue retries cannot turn failure into success.

Pilot acceptance requires complete measured coverage, valid time ranges and
artifact hashes, successful restart/recovery, and reviewed usefulness on the
chosen clips. Define retrieval/annotation targets from that labeled pilot rather
than inventing an accuracy percentage before observing the material. Retain cases
where visual or audio inspection disagrees with the automated result.

## Requirements before removing a local master

Every proposed deletion needs all of the following:

- The original identity is verified, full decoding has completed, and all passes
  required by the selected extraction profile have finished or have an explicit,
  justified not-applicable result. Failures and unresolved required review block it.
- Media, catalog, creation evidence and analysis artifacts are covered by a complete
  immutable backup manifest with current remote-generation/checksum verification.
  A successful media upload alone is insufficient.
- A representative recovery rehearsal has passed for every supported format and
  artifact type, and access configuration is available away from this machine.
  Each clip's backup membership is verified even when its full download is sampled.
- Searchable records and chosen previews remain available locally, and their
  measured storage footprint fits the retention plan.
- Active edits, archived recipes, original paths, alternate takes and shared
  sources have been audited. Clip-library eviction is distinct from deleting
  historical workspace copies; those may preserve dependencies the mirror omits.
- A concrete cleanup manifest identifies exact paths, hashes, recoverable backup
  sets and space savings, followed by explicit cleanup authorization.

The implemented readiness gate only reports blockers and exact proposed master
paths. It performs no deletion. Analysis backup and absent-master sync have offline
failure tests; production readiness still requires the selected profile, reviewed
pilot, current remote verification and an actual recovery rehearsal. Keep local
masters and project archives intact until those conditions and explicit cleanup
authorization are satisfied.
